# 00 · 学习进程（4 周，每天 90 分钟）

> 这份文档回答的不是“学什么”，而是“先学什么、学到什么程度算过关、什么时候进入下一阶段”。

---

## 0. 先看清算法在闭环里的位置

```
                 ┌──────────────┐
   摄像头/电磁 ─→│ 预处理 + 滤波 │─→ e_y, e_psi, kappa
                 └──────────────┘
                          │
                          ▼
                 ┌──────────────┐
                 │ 横向控制器    │──→ delta ──→ 舵机
                 │ PP/Stanley/  │
                 │ LQR/预瞄     │
                 └──────────────┘

   路径/曲率 ───→┌──────────────┐
                 │ 速度规划      │──→ v_target
                 └──────────────┘
                          │
                          ▼
                 ┌──────────────┐
                 │ 纵向控制器    │──→ duty ──→ 电机
                 │ PID          │
                 └──────────────┘

   编码器/IMU ──→ 状态估计 ──→ v, theta, 姿态
```

学习顺序按**数据流从后往前**：

1. 先学“车怎么动”（运动学）
2. 再学“怎么让车听话”（PID）
3. 再学“怎么沿路径走”（路径跟踪）
4. 最后学“怎么知道自己在哪”（感知与状态估计）

原因：前三层在仿真里立刻能验证，不依赖硬件；感知依赖摄像头/电感/光照，变量多、反馈慢，放后面学不会被卡住。

## 1. 四个阶段与过关条件

| 阶段 | 时间 | 主题 | 过关条件（答不上来不要进入下一阶段） |
|---|---|---|---|
| 一 | 第 1 周 | 运动学 + PID | 能解释差速/阿克曼模型、积分饱和、串级带宽 |
| 二 | 第 2 周 | 路径跟踪 + 感知 | 能解释纯跟踪切内线、Stanley 前馈、LQR 权重 |
| 三 | 第 3 周 | 速度规划 + 系统整合 | 能画出完整控制框图，算出刹车距离 |
| 四 | 第 4 周起 | 移植上车 | 开环方向全对，台架通过，低速能跑 |

## 2. 每天 90 分钟的固定流程

不要“今天看三篇文档”。每天只做一轮：

| 时间 | 动作 |
|---|---|
| 5 min | 看昨天最后写的三行记录 |
| 20 min | 读当天文档的一节（只读一节） |
| 20 min | 读对应的一个函数，逐行看懂 |
| 35 min | 动手：改一个参数或一段代码，跑一次 |
| 10 min | 写三行：改了什么 / 结果 / 为什么 |

**三行记录模板**（建议单独建一个 `notes.md`）：

```
Day 4：把 speed_pid 的 out_min/out_max 改成 [0,1]，去掉抗饱和。
结果：超调从 5% 变成 28%，退饱和慢了 0.6 s。
原因：误差大时积分一直累加，输出早就顶到 1 了。
```

## 3. 第 1 周：控制主线

这一周完全不碰摄像头和电感，只在仿真里学“车怎么动、怎么控制”。

### Day 1 · 跑通，建立坐标直觉

**目标**：知道每个目录干什么，建立“改一个地方 → 看结果”的循环。

- 读：`README.md` 的「代码约定」+ `docs/01` 第 0 节
- 做：
  ```sh
  cd /data/user/0/cc.codroid/files/home/workspace/smartcar-algo
  make all
  ```
  打开 `out/sim_compare.html`，把三条轨迹、误差曲线、速度曲线各看一遍。
- 写：一张符号表，至少包含 `x/y/theta`、`v/w`、`delta`、`e_y`、`e_psi`。
- 过关：
  - `e_y > 0` 表示车在路径哪一侧？
  - `delta > 0` 是左转还是右转？
  - 测试一共多少项通过？

### Day 2 · 差速运动学与航迹推算

**目标**：理解“轮速 → 车体速度 → 位姿”的链路，以及为什么积分方法会影响精度。

- 读：`docs/01` 第 1 节
- 看：`src/kinematics.c` 里的 `sc_diff_forward`、`sc_diff_inverse`、`sc_diff_odometry`
- 做（故意改错，看测试怎么失败）：
  ```sh
  git checkout -b exp/odometry-euler
  ```
  把 `sc_diff_odometry` 的圆弧积分换成欧拉：
  ```c
  pose->x += v * cosf(pose->theta) * dt;
  pose->y += v * sinf(pose->theta) * dt;
  pose->theta = sc_wrap_pi(pose->theta + w * dt);
  ```
  然后 `make test`，记录失败的是哪一条、误差多大。
  ```sh
  git checkout main
  ```
- 过关：
  - `v=1, w=1` 走 2π 秒为什么应该回到原点？
  - 欧拉积分为什么回不去？误差随什么增长？

### Day 3 · 阿克曼转向

**目标**：理解前轮转角、曲率、内外轮差异。

- 读：`docs/01` 第 2 节
- 看：`sc_ackermann_steer_from_curvature`、`sc_ackermann_wheel_angles`、`sc_ackermann_integrate`
- 做：
  1. 手算 `L=0.3, W=0.2, delta=0.3` 的内外轮角，再和测试输出对比。
  2. 写一个 20 行的小程序，用 `sc_ackermann_integrate` 让车以 `delta=0.3` 走 10 秒，打印轨迹。
  3. 把 `max_steer` 改成 0.1，看 `sc_ackermann_steer_from_curvature` 怎么限幅。
- 过关：
  - 写出阿克曼条件 `cot δo - cot δi = W/L`。
  - 为什么控制器和定位必须用同一个参考点（后轴/前轴）？

### Day 4 · PID 基础

**目标**：把 P、I、D 三项分别“看见”。

- 读：`docs/05` 第 1–4 节
- 看：`src/pid.c` 的 `pid_position_update`
- 做：新建 `scratch/pid_step.c`：

  ```c
  #include <stdio.h>
  #include "sc/pid.h"

  int main(void) {
      sc_pid_t pid;
      sc_pid_init(&pid, 2.0f, 4.0f, 0.02f);
      sc_pid_set_limits(&pid, -10.0f, 10.0f);

      float y = 0.0f, dt = 0.01f;
      for (int i = 0; i < 500; i++) {
          float u = sc_pid_update(&pid, 1.0f, y, dt);
          y += dt * (u - y) / 0.2f;   /* 一阶对象，τ=0.2s */
          printf("%.3f,%.4f\n", i * dt, y);
      }
      return 0;
  }
  ```

  ```sh
  mkdir -p scratch
  cc -std=c11 -Iinclude scratch/pid_step.c src/*.c -lm -o scratch/pid_step
  ./scratch/pid_step > scratch/pid.csv
  ```

  跑三组：只给 `kp`；给 `kp+ki`；给 `kp+ki+kd`。观察超调和调节时间。
- 再做一次：把 `sc_pid_set_limits(&pid, 0.0f, 1.0f)`，把 `ki` 调大，看积分饱和怎么让退饱和变慢。
- 过关：
  - 积分饱和是什么？为什么输出限幅后还会超调？
  - 微分冲击是什么？`derivative_on_measurement` 解决什么问题？
  - 死区给太大会发生什么？

### Day 5 · PID 进阶与串级

**目标**：理解前馈、串级、模糊 PID 的位置。

- 读：`docs/05` 第 5–7 节
- 看：`sc_pid_update_ff`、`sc_fuzzy_pid_update`（先看结构，不抠规则表）
- 做：
  1. 在 Day 4 的程序里给 `sc_pid_update_ff` 加一个常数前馈，看稳态误差怎么变。
  2. 画一张串级框图：外环位置/角度 → 内环速度/角速度。
  3. 把模糊 PID 的 `e_range` 从 1.0 改成 0.2，观察输出。
- 过关：
  - 为什么内环带宽要比外环高 3~5 倍？
  - 前馈和反馈分别解决什么问题？

### Day 7 · Stanley

### Day 8 · LQR

- 读：`docs/06` 第 4 节

### Day 9 · 感知（摄像头或电磁，只选一个）

  2. 把 `max_jump` 从 5 改成 2 和 20，观察边线跟踪什么时候断。
  3. 改合成图像里的半宽，模拟宽窄不同的赛道。
- 过关：二值化为什么用 `<=` 而不是 `<`？`max_jump` 太大/太小分别会怎样？

**电磁组**：

  1. 用 `sc_emag_sim_field` 生成五路数据，分别用差比和、二次拟合、加权质心算偏移。
  2. 改变导线位置（-0.1 ~ +0.1 m），画三条“真实偏移 vs 计算偏移”曲线。

## 6. 第 4 周起：移植上车

### Day 16–17 · 移植准备

- 读：`docs/09`
- 做：
  1. 列出你的主控外设清单：编码器定时器、PWM、ADC、摄像头接口、IMU 接口。
  2. 写一个 `hal.h`，把算法需要的输入输出抽象出来（读编码器、读 IMU、设 PWM、设舵机）。
  3. 估算内存：图像缓冲区、路径数组、各结构体。
- 过关：算法层不直接调用任何寄存器，只调用 `hal`。

### Day 18–19 · 台架测试

按顺序，每步通过再下一步：

1. 电机悬空：正转/反转、编码器符号、PWM 限幅。
2. 舵机：中值、左右极限、斜率、不顶死。
3. IMU：静止时角速度接近 0，倾角正确。
4. 摄像头/电感：能看到干净的二值图/归一化曲线。
5. 开环：给固定 `delta`，车走预期方向；给固定占空比，车走预期速度。

### Day 20 · 低速落地

- 1 m/s 直线 → 1 m/s 弯道 → 1.5 m/s → 2 m/s，每次只改速度。
- 每圈记录：最大误差、是否出界、电池电压。
- 对照 `docs/09` 的移植检查清单逐项打勾。

## 8. 卡住时的处理顺序

1. **先开环**：固定输入，看输出方向对不对。
2. **再单模块**：只测运动学/只测 PID，不要整车联调。
3. **再打印**：把关键变量打到串口/CSV，不要靠猜。
4. **最后才调参**：确认符号、单位、参考点都对，再动增益。
5. **一次只改一个参数**，改了立刻记录。

## 9. 这个进程的核心

不是“看完 9 篇文档”，而是：

> 每学一个算法，都能在仿真里改一个地方、看到一个变化、用自己的话解释为什么。

做到这一点，20 天后你对智能车电控的理解，会比“刷完所有教程”扎实得多。
