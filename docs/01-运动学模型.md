# 01 · 车辆运动学模型

> 代码：`include/sc/kinematics.h`、`src/kinematics.c`
> 测试：`tests/test_main.c` 里的 `test_kinematics`

运动学回答一个问题：**轮子怎么转，车体怎么走**。它不涉及力、质量、轮胎滑移，是控制器设计的地基。智能车电控里 80% 的“方向反了”“原地画圈越跑越偏”，都能在运动学层面找到原因。

---

## 0. 全工程统一的坐标与符号

```
        y (左)
        ↑
        │
        │       车头
        │      ↗
        │    θ
        └──────────→ x (前)
```

- 车体坐标：x 向前，y 向左，z 向上（右手系）。
- `theta`：车头相对世界 x 轴的转角，逆时针为正。
- `w > 0`：左转（逆时针）。
- 前轮转角 `delta > 0`：左转。
- 单位：米、秒、弧度。

移植到自己的代码时，**先写一张符号表**，把所有传感器的正方向标出来。符号错一次，后面调一周。

## 1. 差速驱动

适用：两轮差速、履带车、双电机独立驱动、平衡车的轮组。

### 1.1 正逆解

设左右轮中心距（轮距）为 `L`，左右轮线速度 `v_l`、`v_r`。

正解：

```
v = (v_l + v_r) / 2
w = (v_r - v_l) / L
```

逆解：

```
v_l = v - w * L / 2
v_r = v + w * L / 2
```

代码：

```c
sc_diff_forward(&d, v_left, v_right, &v, &w);
sc_diff_inverse(&d, v, w, &v_left, &v_right);
```

几个容易混的点：

- `L` 是**左右轮中心距**，不是车宽，也不是轮子外缘距离。
- 轮距标定误差 5%，原地转 10 圈后航向误差就有 18°。
- 如果车往右偏而你想让它往左，先检查 `w` 的符号，再检查电机接线，不要直接改 PID 符号。

### 1.2 编码器测速

编码器给出的是脉冲数。换算成轮速：

```
电机转数   = 脉冲数 / PPR
车轮转数   = 电机转数 / 减速比
行驶距离   = 车轮转数 * 2π * r
轮速       = 行驶距离 / dt
```

```c
float v = sc_diff_wheel_speed(&d, delta_counts, dt);
```

`PPR` 要用**四倍频后的计数**。正交编码器 A/B 两相，上升沿和下降沿都计数，实际是 `线数 × 4`。

低速时一个控制周期可能只有几个脉冲，量化噪声很大。两种处理：

1. M/T 法：低速测周期，高速测频率。
2. 速度环前面加一阶低通或滑动平均（见 `docs/04`）。

### 1.3 航迹推算（Odometry）

最朴素的欧拉积分：

```
x += v cos(theta) dt
y += v sin(theta) dt
theta += w dt
```

它在直线和小角度下够用，但**原地旋转或大曲率**时会丢位置：车其实沿圆弧走，欧拉法把它当成先转再直走。

精确圆弧积分：

```
R = v / w
dtheta = w dt
x += R (sin(theta + dtheta) - sin(theta))
y += -R (cos(theta + dtheta) - cos(theta))
theta += dtheta
```

代码里 `sc_diff_odometry` 做了这个处理，并在 `|w| < 1e-5` 时退化为直线，避免除零。

一个直观的验证（单元测试里也有）：

```
v = 1 m/s, w = 1 rad/s, R = 1 m
走 2π 秒，车正好绕半径为 1 的圆一圈，回到原点。
```

欧拉积分会有明显的位置漂移，圆弧积分不会（只有浮点误差）。

### 1.4 标定顺序

1. **轮径**：让车直行 10 m，记录左右编码器总计数，反算轮径。
2. **轮距**：原地缓慢转 10 圈，用陀螺仪积分得到总转角，`L = (v_r - v_l)/w`。
3. **编码器方向**：手推车前进，两个轮速都应为正。
4. **死区**：给最小 PWM，找到轮子刚开始转的占空比（见 `docs/07`）。

## 2. 阿克曼转向（自行车模型）

适用：绝大多数摄像头组、电磁组、越野组。前轮转向、后轮驱动。

### 2.1 自行车模型

把左右前轮合并成一个位于后轴中心的“虚拟前轮”，得到：

```
x_dot     = v cos(theta)
y_dot     = v sin(theta)
theta_dot = v tan(delta) / L
```

其中 `L` 是前后轴距，`delta` 是等效前轮转角。

曲率：

```
kappa = tan(delta) / L
R     = 1 / kappa = L / tan(delta)
```

代码：

```c
float kappa = sc_ackermann_curvature(&car, delta);
float delta = sc_ackermann_steer_from_curvature(&car, kappa);
void  sc_ackermann_integrate(&pose, &car, v, delta, dt);
```

积分用中点法：

```
w = v tan(delta) / L
theta_mid = theta + 0.5 w dt
x += v cos(theta_mid) dt
y += v sin(theta_mid) dt
theta += w dt
```

比一阶欧拉准，代价只是多算一个三角函数。

### 2.2 阿克曼几何：内外轮不一样

转弯时，内侧轮走的圆半径更小，必须比外侧轮转得更多，否则轮胎会侧滑。

设后轴中心到转弯圆心的距离为 `R`，轮距 `W`：

```
R_inner = R - W/2
R_outer = R + W/2

delta_inner = atan(L / R_inner)
delta_outer = atan(L / R_outer)
```

等价关系（阿克曼条件）：

```
cot(delta_outer) - cot(delta_inner) = W / L
```

代码：

```c
float inner, outer;
sc_ackermann_wheel_angles(&car, delta, &inner, &outer);
```

左转时 `delta > 0`，左轮是内轮，`inner > delta > outer`。测试里验证了这个关系。

实车上不一定装阿克曼梯形（很多车用一根横拉杆），这时内外轮转角由连杆几何决定，**不要硬套公式**；但转向时左右轮速差仍然存在，四驱车要允许差速。

### 2.3 前轴参考 vs 后轴参考

上面的模型以**后轴中心**为参考点。有些队伍把摄像头装在车头，用前轴做参考更自然：

```
beta = atan(0.5 tan(delta))          // 车体速度方向相对车头的侧偏角
x_dot = v cos(theta + beta)
y_dot = v sin(theta + beta)
theta_dot = v tan(delta) / L
```

代码：`sc_ackermann_integrate_front`。

两者描述的是同一辆车，只是参考点不同。路径跟踪时**控制器用的参考点必须和定位/投影用的点一致**，否则会有恒定偏移。

### 2.4 舵机映射

舵机不是线性的。常见做法：

```
pwm = pwm_center + k1 * delta + k2 * delta^2
```

`k2` 补偿连杆的非线性。标定：

1. 机械中值：车轮正前方，记 `pwm_center`。
2. 左打满、右打满各记一个点。
3. 用三点拟合 `k1`、`k2`，或者直接做查表。

代码见 `servo.c`，还带斜率限制，防止舵机被阶跃指令打坏。

## 3. 麦克纳姆轮

适用：麦轮组、需要横移和原地旋转的场景。

四个轮子，辊子与轮轴成 45°。轮序约定（代码里）：

```
0 = 左前 FL
1 = 右前 FR
2 = 左后 RL
3 = 右后 RR
```

逆解（车体速度 → 四个轮子的角速度，rad/s）：

```
ω_FL = ( vx - vy - (lx+ly) wz ) / r
ω_FR = ( vx + vy + (lx+ly) wz ) / r
ω_RL = ( vx + vy - (lx+ly) wz ) / r
ω_RR = ( vx - vy + (lx+ly) wz ) / r
```

矩阵形式（右边整体再除以 r）：

```
[ ω_FL ]   [ 1  -1  -(lx+ly) ] [ vx ]      1
[ ω_FR ] = [ 1   1   (lx+ly) ] [ vy ]  ·  ---
[ ω_RL ]   [ 1   1  -(lx+ly) ] [ wz ]      r
[ ω_RR ]   [ 1  -1   (lx+ly) ]
```

正解是伪逆（先把角速度乘 r 换成轮面线速度）：

```
x_i = r * ω_i

vx = ( x_FL + x_FR + x_RL + x_RR ) / 4
vy = (-x_FL + x_FR + x_RL - x_RR ) / 4
wz = (-x_FL + x_FR - x_RL + x_RR ) / (4 (lx+ly))
```

其中 `lx` 是半轴距，`ly` 是半轮距。

**最容易错的地方**：辊子旋向。不同厂家的麦轮，左右轮的辊子镜像安装。如果发现“前进正常、横移反了”，不要改整车符号，把对应轮公式里的 `vy` 符号取反即可。判断方法：手推车沿 +y 方向平移，看四个轮子的转向是否符合你的公式。

麦轮还有一个现实问题：辊子打滑导致里程计不准。横移时误差尤其大，不要指望麦轮编码器做高精度定位。

## 4. 三轮全向轮

三个全向轮按 120° 分布，默认安装角 `90°、210°、330°`。

对第 i 个轮子，安装方位角 `alpha_i`：

```
ω_i = (-sin(alpha_i) vx + cos(alpha_i) vy) / R + wz
```

逆解（三个轮子角速度 → 车体速度）：

```
vx = -(2/3) R Σ sin(alpha_i) ω_i
vy =  (2/3) R Σ cos(alpha_i) ω_i
wz =  (1/3) Σ ω_i
```

代码：`sc_omni3_inverse` / `sc_omni3_forward`，测试里做了正逆解往返验证。

安装角有 1° 误差，走 1 m 就会偏几厘米。全向轮对机械安装精度比麦轮更敏感。

## 5. 平衡车 / 独轮车

平衡车本质是**倒立摆**。经典线性化模型（状态 `[位置, 速度, 倾角, 角速度]`，输入水平推力 `F`）：

```
A = [ 0   1   0          0        ]
    [ 0   0  -m g / M     0        ]
    [ 0   0   0          1        ]
    [ 0   0  (M+m) g/(M l) 0       ]

B = [ 0, 1/M, 0, -1/(M l) ]^T
```

其中 `M` 是轮组质量，`m` 是车身质量，`l` 是质心到轮轴距离。

代码：

```c
sc_balance_t b = { .cart_mass = 1.0f, .pole_mass = 0.5f,
                   .pole_half = 0.3f, .g = 9.81f };
float A[4][4], B[4];
sc_balance_state_space(&b, A, B);

float K[4];
sc_lqr_balance(1.0f, 0.5f, 0.3f,
               1.0f, 1.0f, 10.0f, 1.0f,  // 位置/速度/角度/角速度权重
               0.1f, K);
```

得到 `K` 后，控制律是 `F = -K x`。角度权重给大，车才“愿意”保持直立；位置权重给大，车会更积极地回到原点。

实车上还要加：

- 直立环（角度 PD）
- 速度环（编码器）
- 转向环（差速）
- 输出限幅和死区补偿

LQR 给的是线性最优解，前提是模型近似成立；轮胎打滑、重心变化、地面摩擦都会让 `K` 需要重调。

## 6. 一张表总结

| 模型 | 状态 | 输入 | 关键参数 | 典型用途 |
|---|---|---|---|---|
| 差速 | v, w | v_l, v_r | 轮距 L、轮径 r | 双电机、履带、平衡车轮组 |
| 阿克曼 | x, y, θ | v, δ | 轴距 L、轮距 W | 摄像头/电磁/越野 |
| 麦轮 | x, y, θ | 4 轮速 | lx, ly, r | 麦轮组 |
| 全向三轮 | x, y, θ | 3 轮速 | 安装角、r | 全向组 |
| 倒立摆 | x, ẋ, θ, θ̇ | 推力 F | M, m, l | 平衡组、独轮 |
