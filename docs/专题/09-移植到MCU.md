# 09 · 移植到 MCU

> 目标平台：STM32F4/H7、NXP RT1064、Infineon TC264、GD32 等常见智能车主控。

这套代码是按“可移植”写的：

- 纯 C99，没有 C++、没有动态内存、没有文件 IO。
- 所有状态在结构体里，调用方负责分配。
- 不依赖操作系统。
- 单位统一，没有隐藏的全局状态。

但“能编译”不等于“能跑好”。这一章讲移植时要处理的现实问题。

---

## 1. 拷贝哪些文件

最小集合：

```
include/sc/*.h
src/*.c
```

按需裁剪：

- 只做电磁 → 不要 `camera_line.c`。
- 不做麦轮 → 不要 `kinematics.c` 里的麦轮部分（链接器会自动去掉未用的函数，但可以手动删）。
- 不用 LQR → 不要 `linalg.c`、`lqr.c`。

保留 `math_utils.c`、`filter.c`、`pid.c` 作为基础。

## 2. 编译选项

```makefile
CFLAGS = -std=c11 -O2 -Wall -Wextra -ffunction-sections -fdata-sections
LDFLAGS = -Wl,--gc-sections
```

- `-ffunction-sections -fdata-sections` + `--gc-sections`：去掉没用到的函数，省 Flash。
- 不要用 `-ffast-math` 除非你清楚它在做什么（可能改变 `NaN`/`Inf` 行为，影响安全检查）。
- 浮点常量加 `f` 后缀，避免隐式转 `double`。代码里已经这么写了。

如果是 Keil/IAR，把 `src/*.c` 加入工程，`include` 加入头文件路径即可。

## 3. 浮点 vs 定点

### 3.1 有 FPU

Cortex-M4F/M7、TC264、RT1064 都有单精度 FPU。直接用 `float`，性能足够：

- 200 Hz 控制循环，每次几百次浮点运算，占用不到 1% CPU。
- `sinf`、`cosf`、`atan2f` 是开销大头，但也能接受。

注意：

- 用 `float`，不要用 `double`。M4 的 double 是软件模拟，慢几十倍。
- 编译选项确认开启了 FPU（`-mfpu=fpv4-sp-d16 -mfloat-abi=hard`）。

### 3.2 没有 FPU

Cortex-M0/M3、部分 8 位机。两个选择：

1. **软浮点**：能用，但慢。200 Hz 可能跑不动复杂的 LQR。
2. **定点数**：Q 格式。

Q15 示例：

```c
typedef int32_t q15_t;   // 范围 [-1, 1)，分辨率 1/32768

static inline q15_t q15_mul(q15_t a, q15_t b) {
    return (q15_t)(((int64_t)a * b) >> 15);
}

static inline q15_t q15_div(q15_t a, q15_t b) {
    return (q15_t)(((int64_t)a << 15) / b);
}
```

角度可以用 Q12（分辨率约 0.00024 rad）。PID 用 Q15 足够。

定点化的难点是**动态范围**：误差可能很小（毫米级），积分可能很大。要仔细选 Q 值，或者混合使用（误差用 Q15，积分用 Q20）。

建议：能上 M4 就上 M4，别在定点上耗时间。

## 4. 内存占用

大致估算（32 位平台）：

| 结构体 | 大小 | 说明 |
|---|---:|---|
| `sc_pid_t` | ~64 B | 14 个 float + 状态 |
| `sc_fuzzy_pid_t` | ~100 B | 含 PID |
| `sc_adrc_t` | ~80 B | |
| `sc_mahony_t` | ~56 B | |
| `sc_emag_t` | ~350 B | 8 通道 |
| `sc_edge_t` | ~2 KB | 128 行 × 4 个 int |
| `sc_lqr_track_t` | ~300 B | 含 8×8 矩阵 |
| `sc_path_t` | ~40 B | 数组在外部 |

图像缓冲区是大头：

| 分辨率 | 灰度缓冲 |
|---|---:|
| 160×120 | 19.2 KB |
| 320×240 (QVGA) | 76.8 KB |
| 640×480 | 307 KB |

很多主控的 SRAM 只有 128~512 KB。策略：

- 只开 ROI（感兴趣区域），比如图像下半部分。
- 用二值图（1 bit/px）而不是灰度图。
- 边扫边处理，不存整帧。

代码里 `sc_image_t` 只是指针，缓冲区由调用方提供：

```c
static uint8_t img_buf[160 * 120];
static uint8_t bin_buf[160 * 120];
```

## 5. 任务架构

典型的分层调度（1 ms 基准 tick）：

| 任务 | 周期 | 内容 |
|---|---|---|
| 电机 PWM | 10~20 kHz | 硬件定时器，不用 CPU |
| 编码器 | 1 ms | 读计数、算速度 |
| IMU | 1~5 ms | SPI/I2C 读、姿态解算 |
| 控制 | 5~10 ms | 路径跟踪、PID、输出 |
| 电磁 ADC | 1~5 ms | DMA + 滤波 |
| 摄像头 | 20~50 ms | 采集、二值化、边线 |
| 调试输出 | 20~100 ms | 串口/无线 |

实现方式：

- 裸机：`SysTick` 置标志，主循环轮询。
- RTOS：每个任务一个优先级，控制任务最高。

不要在中断里做重活。中断只做“读数据、置标志”，算法放主循环。

### 5.1 一个最小调度器

```c
volatile uint32_t g_ms;

void SysTick_Handler(void) { g_ms++; }

int main(void) {
    init_all();

    uint32_t t_ctrl = 0, t_imu = 0, t_cam = 0;

    while (1) {
        uint32_t now = g_ms;

        if (now - t_imu >= 2) {
            t_imu = now;
            imu_task();
        }
        if (now - t_ctrl >= 5) {
            t_ctrl = now;
            control_task();
        }
        if (now - t_cam >= 20) {
            t_cam = now;
            camera_task();
        }

        watchdog_feed();
    }
}
```

这种写法简单，但任务会互相延迟。要求严格时用定时器中断触发控制任务，或用 RTOS。

### 5.2 控制任务

```c
void control_task(void) {
    /* 1. 读传感器 */
    float v = encoder_get_speed();
    float e_y, e_psi;
    perception_get_error(&e_y, &e_psi);

    /* 2. 路径跟踪 */
    float delta_cmd = sc_lqr_track_update(&g_lqr, e_y, e_psi, g_kappa);

    /* 3. 舵机 */
    float pwm = sc_servo_update(&g_servo, delta_cmd, 0.005f);
    servo_set_pwm(pwm);

    /* 4. 速度 */
    float v_target = g_v_target;
    float duty = sc_pid_update(&g_speed_pid, v_target, v, 0.005f);
    duty = sc_motor_update(&g_motor, duty, 0.005f);
    motor_set_duty(duty);
}
```

## 6. 外设映射

| 算法需要 | 外设 | 注意 |
|---|---|---|
| 编码器 | 定时器编码器模式 / 外部中断 | 四倍频、方向、溢出 |
| 电机 PWM | 定时器 PWM | 死区、互补、频率 10~20 kHz |
| 舵机 PWM | 定时器 PWM | 50~300 Hz，1~2 ms 脉宽 |
| 电磁 | ADC + DMA | 采样同步、滤波 |
| 摄像头 | DCMI + DMA / 并口 | 帧同步、双缓冲 |
| IMU | SPI / I2C | 中断、FIFO、量程 |
| 调试 | UART / 无线 | 不要阻塞控制循环 |

### 6.1 编码器溢出

16 位定时器在低速时可能溢出。用 `int16_t` 读差值，或者开启溢出中断累加。

```c
int16_t delta = (int16_t)(now - last);
last = now;
```

### 6.2 舵机 PWM

50 Hz（20 ms 周期），脉宽 1.0~2.0 ms 对应 -90°~+90°。有些数字舵机支持 300 Hz，响应更快。

计算：

```
ARR = 定时器时钟 / 频率 - 1
CCR = 脉宽(us) * 定时器时钟(MHz) / 预分频
```

具体公式看主控手册。

## 7. 数学函数

### 7.1 三角函数

`sinf`、`cosf` 在 M4 上大约几十到几百个周期。200 Hz 调用几次没问题，但如果在 1 kHz 中断里大量调用，会吃满 CPU。

优化：

- 查表 + 线性插值（256 点表，误差 < 0.01%）。
- 只在必要时算，比如纯跟踪的 `atan2f` 可以用近似公式。
- 把常量三角函数提前算好。

### 7.2 atan2

纯跟踪、Stanley 都用到 `atan2f`。快速近似：

```
atan(x) ≈ x - x³/3 + x⁵/5  (|x| < 1)
```

再根据象限调整。误差约 0.01 rad，对转向够用。

### 7.3 除零保护

代码里大部分除法都有 `if (fabs < eps)` 保护。移植时不要删掉，传感器异常时会返回 0/NaN。

## 8. 安全

### 8.1 看门狗

```c
watchdog_feed();  // 只在所有任务都正常时喂
```

如果摄像头任务卡死，不要喂狗，让系统复位。

### 8.2 失控保护

- 摄像头超时 → 用上一帧误差，或者减速停车。
- IMU 超时 → 禁用依赖姿态的功能。
- 编码器异常 → 限速。
- 电池低压 → 降速。

### 8.3 输出限幅

所有执行器输出都要限幅：

```c
pwm = sc_clampf(pwm, PWM_MIN, PWM_MAX);
duty = sc_clampf(duty, -1.0f, 1.0f);
```

不要依赖机械限位。

### 8.4 上电流程

```
1. 关电机、舵机回中
2. 陀螺零漂校准（车必须静止）
3. 传感器自检
4. 等待发车信号
5. 使能电机
```

不要在陀螺没校准完就发车。

### 8.5 急停

软件急停 + 硬件急停（拨杆/遥控）。软件急停要能立即切断电机 PWM。

## 9. 测试

### 9.1 PC 上跑单元测试

`make test` 在 PC 上验证算法数值正确。移植后，把同样的测试跑在目标板的 `main` 里（用串口输出结果），确认编译器/浮点行为一致。

### 9.2 半实物（HIL）

- 用 PC 生成传感器数据，通过串口/CAN 发给主控。
- 主控算控制量，回传给 PC 验证。

### 9.3 台架测试

- 车架起来，轮子悬空：验证电机方向、编码器符号、PWM 限幅。
- 舵机单独测试：中值、左右极限、斜率。
- 摄像头对着打印的赛道：验证二值化、边线。

### 9.4 低速落地

先 1 m/s，再 2 m/s，逐步加。每次只改一个参数。

## 11. 常见移植坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 控制周期抖动 | 主循环任务阻塞 | 用定时器中断触发控制 |
| 浮点结果和 PC 不一致 | `double` 被截断、优化等级不同 | 统一用 `float`，加 `f` 后缀 |
| 栈溢出 | 大数组放局部变量 | 改 `static` 或全局 |
| 电机啸叫 | PWM 频率在人耳范围 | 提高到 16~20 kHz |
| 编码器丢脉冲 | 中断优先级低/没开 | 提高优先级，用硬件编码器 |
| 摄像头撕裂 | 没等帧同步 | 双缓冲/帧中断 |
| 舵机抖 | PWM 分辨率不够 | 提高定时器时钟 |
| 复位后车冲出去 | 上电未初始化输出 | 先关电机再初始化 |
