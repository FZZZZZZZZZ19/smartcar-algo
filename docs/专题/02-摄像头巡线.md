# 02 · 摄像头巡线

> 代码：`include/sc/camera_line.h`、`src/camera_line.c`
> 测试：`test_camera`

摄像头巡线的流程可以拆成五步：

```
灰度图 → 二值化 → 提取边线/中线 → 计算偏差和曲率 → 识别赛道元素
```

每一步都有坑。这一章按流程讲，最后给一份实车调参清单。

---

## 0. 图像与坐标

代码里的图像：

```c
typedef struct {
    uint8_t *data;   // 灰度，0~255
    int width;
    int height;
} sc_image_t;
```

`data[0]` 是左上角，行优先。图像坐标 `(u, v)`：`u` 向右，`v` 向下。

这和数学坐标的 y 轴相反。算曲率时要把 `v` 取负，否则左弯会算成右弯。

---

## 1. 二值化

### 1.1 固定阈值

最简单：

```c
sc_binarize(&img, bin, 100, /*line_is_dark=*/1);
```

优点：快、可预测。缺点：光照一变就废。适合赛道光照稳定、且有自动曝光锁定的场地。

### 1.2 大津法（Otsu）

自动找让“类间方差最大”的阈值。直方图分两堆，取使 `w0*w1*(m0-m1)^2` 最大的 `t`。

```c
uint8_t th = sc_otsu(&img);
sc_binarize(&img, bin, th, 1);
```

代码里有个细节：判断暗像素用 `src <= threshold`，不是 `<`。因为 Otsu 在两峰之间任意阈值都等价，返回的可能是暗峰的精确值；用 `<` 会把整个暗峰判成亮，图像直接翻转。

### 1.3 自适应阈值

赛道上有阴影、反光时，全局阈值不够。常用：

- 分块 Otsu：把图像切成 4×4 块，每块单独求阈值。
- 按行求阈值：每一行单独 Otsu，适合光照沿纵向变化。
- 大津法 + 灰度拉伸：先统计最小/最大值，归一化后再 Otsu。

比赛里更常见的做法是**锁曝光**：手动把摄像头曝光、增益固定，让光照尽量一致，然后放心用固定阈值。

## 2. 八邻域爬线

适用：单根黑线（电磁/摄像头循迹）、需要沿一条线提取中心路径的场景。

### 2.1 算法

从底部一个种子点出发，在 8 个邻居里找下一个线像素。为了让 1 像素细线不左右抖，搜索顺序按“方向连续性”排：

```
方向编号（0=上，顺时针）：
    7 0 1
    6 ● 2
    5 4 3

搜索顺序：当前方向 → 左右偏 1 → 左右偏 2 → 左右偏 3 → 回头
```

代码：

```c
int sc_trace_8(const uint8_t *bin, uint8_t *visited, int width, int height,
               int x0, int y0, sc_point_t *pts, int max_pts);
```

`visited` 必须是 `width*height` 的缓冲区且清零，防止绕圈。

停止条件：

- 到图像顶部
- 8 个邻居都没有未访问的线像素（断线）
- 点数达到 `max_pts`

### 2.2 失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 爬到一半断掉 | 线太细、二值化丢了 | 膨胀/降低阈值 |
| 在交叉口乱跳 | 8 邻域分叉 | 记录上一方向，优先直行；或改用边线扫描 |
| 左右抖动 | 线宽 1 px，邻居选择不稳定 | 对中心点做滑动平均 |
| 跑到别的线上 | 赛道有两条线 | 限制横向搜索范围 |

八邻域爬线适合“一条线”的场景。摄像头组赛道是两条边线围成的带状区域，更适合下面的边线扫描。

---

## 3. 边线扫描

### 3.1 思路

从图像底部开始，一行一行往上扫。每行从上一行的中心附近找一段连续的赛道像素，记录左右边界：

```
for y = bottom; y >= top; y--:
    run = 从 seed 向两边扩展的连续赛道像素
    left[y]  = run.start
    right[y] = run.end
    center[y] = (left+right)/2
    seed = center[y]      // 下一行从这里找
```

代码：

```c
sc_edge_t e;
sc_scan_edges(bin, width, height,
              /*y_bottom=*/height - 1,
              /*y_step=*/-1,
              /*rows=*/80,
              /*center_x=*/width / 2,
              /*max_jump=*/5,
              /*min_width=*/5,
              &e);
```

### 3.2 三个关键参数

- `max_jump`：每行相对上一行允许的最大横向跳变。太小会在大弯道丢线，太大会在十字路口跳到另一条边。
- `min_width`：有效赛道的最小宽度。过滤噪点。
- `rows`：扫描多少行。不是越多越好；远端像素少、噪声大，通常只用下半部分。

### 3.3 丢线处理

`left[i] = -1` 表示这一行没找到。不要直接当中线 0 用，会引入巨大跳变。常见处理：

1. 用上一行的中心外推。
2. 用相邻有效行插值。
3. 记录丢线行数，作为元素识别的特征（十字、环岛都会丢线）。

### 3.4 中线

最直接：`center = (left + right) / 2`。

但左右边线的可信度不一样：弯道内侧的边线常常被车身挡住或出画。可以给两边加权：

```
center = (w_l * left + w_r * right) / (w_l + w_r)
```

`w_l`、`w_r` 根据边线是否丢失、距离图像边缘的远近动态调整。

`sc_edge_smooth_center` 做了一个简单的窗口平均，去掉孤立跳变。

## 4. 曲率

### 4.1 三点法

取中线上三个点，用外接圆曲率：

```
a = P1 - P0
b = P2 - P0
cross = a.x*b.y - a.y*b.x
kappa = 2 * cross / (|a| |b| |P2-P1|)
R = 1 / kappa
```

代码：`sc_curvature_3pt`（返回半径），`sc_centerline_curvature_px`（像素空间曲率）。

符号：逆时针为正。图像坐标 y 向下，所以调用前要取负。

### 4.2 数值稳定性（很重要）

三点越接近共线，`cross` 越小，浮点误差占比越大。单元测试里踩过这个坑：

```
半径 2 m 的圆，采样间隔 0.2 m，曲率能算到 0.51；
采样间隔 0.1 m，算出来 0.98 —— 完全错了。
```

原因：三点几乎在一条直线上，`cross` 是两个大数相减，float 的有效位不够。

对策：

- 三点之间的弧长间隔不要太小，经验上 `ds >= 0.2~0.3 m`。
- 用路径上更远的点，或者先对中线做拟合（最小二乘圆/二次曲线）再求曲率。
- 用 `double` 做这一步，或者把坐标平移到局部原点再算。

### 4.3 像素曲率 vs 物理曲率

像素空间的曲率受透视影响，远处的一小段在图像上可能很长。要做速度规划，必须转成物理曲率。

两种方法：

1. 逆透视（IPM）把中线转到地面坐标，再算曲率。
2. 用相机模型直接对每一点求导。

代码提供 IPM 版本：

```c
sc_point2f_t ground[128];
int n = sc_centerline_to_ground(&e, &cam, ground, 128);
float kappa = sc_ground_curvature(ground, n);
```

## 5. 逆透视（IPM）

### 5.1 推导

相机离地高度 `H`，镜头向下俯仰 `p`（向下为正），焦距 `f`（像素）。

像素 `(u, v)` 对应的相机坐标射线：

```
xc = u - cx      // 右
yc = v - cy      // 下
zc = f           // 前
```

转到世界坐标（前 F、左 L、上 U）。相机绕右轴向下转 `p`：

```
F = -yc sin(p) + zc cos(p)
L = -xc
U = -yc cos(p) - zc sin(p)
```

射线打到地面（高度 `-H`）的参数：

```
t = H / (-U)
x = t F      // 前向距离
y = t L      // 横向距离（左正）
```

代码：`sc_ipm_pixel_to_ground`。反变换 `sc_ipm_ground_to_pixel` 用于在图上画预测轨迹，测试里做了往返验证。

### 5.2 标定

- `H`：卷尺量相机光心到地面。
- `f`：用已知距离的标定板，或者查摄像头模组参数。
- `p`：最容易错。可以让车停在直道上，看图像里赛道中线是否关于图像中心对称；不对称就调 `p` 和 `cx`。
- `cx, cy`：主点，通常接近图像中心，但不一定正好是 `w/2, h/2`。

标定完做一次验证：在离车 1 m、2 m、3 m 处各放一个标志物，看 IPM 算出来的距离是否对得上。

### 5.3 IPM 的局限

- 只对**平面**成立。坡道、起伏会让距离算错。
- 远处像素少，IPM 会把噪声放大。通常只用到图像下半部分。
- 俯仰角随车姿态变化（加速抬头、刹车点头），需要 IMU 补偿，或者接受误差。

## 6. 赛道元素识别

`sc_classify_element` 是一个骨架，用三个特征做粗分类：

```c
typedef struct {
    float curvature_px;
    float width_mean;
    float width_jump;
    int   left_lost;
    int   right_lost;
    int   both_lost;
    int   rows;
} sc_track_feat_t;
```

规则：

| 特征 | 判断 | 可能元素 |
|---|---|---|
| 大面积丢线 | `both_lost / rows > 0.45` | 十字、出赛道 |
| 宽度突变 | `width_jump > 阈值` | 十字、环岛入口 |
| 曲率大 | `|curvature| > 阈值` | 弯道 |
| 宽度持续变小 | 平均宽度骤降 | 障碍、窄道 |
| 单边持续丢线 | 一侧丢失很多行 | 环岛 |

**这只是起点。** 真实赛道元素识别通常是一个状态机：

```
直道 → 检测到宽度突增 → 进入"疑似十字" →
  持续 N 帧宽度都大 → 确认十字，保持直行
  否则 → 回到直道

直道 → 单边丢线持续 M 行 → 进入"疑似环岛" →
  根据丢线方向决定入环/出环
```

几个实战经验：

- **不要用单帧做决定。** 加计数器/状态机，连续 N 帧满足才切换。
- **十字**：两侧边线同时向外跳，宽度突然变大，且中线仍然连续。
- **环岛**：一侧边线消失，另一侧还在；入环和出环的丢线方向相反。
- **坡道**：图像整体变亮/变暗，宽度变化不一定明显；很多队伍用 IMU 的俯仰角辅助。
- **障碍**：宽度突然变窄，且持续若干行。
- **赛道记忆**：记录上一圈的元素顺序和里程，第二圈用里程触发，比纯图像更稳。

## 7. 实车调参清单

按顺序检查，别跳步：

1. **曝光**：手动锁定，让白赛道不饱和、黑边线不糊。
2. **二值化**：把二值图存到屏幕/上位机看，确认边线干净。
3. **扫描范围**：只取图像下半部分，减少远端噪声。
4. **`max_jump`**：从 3 开始加，直到大弯道不丢线。
5. **中线**：静止时中线应该是一条平滑曲线，不应有锯齿。
6. **曲率**：手推车沿已知半径的弯走，对比算出来的曲率。
7. **元素阈值**：每个元素单独录数据，统计特征分布，再定阈值。
8. **上车闭环**：先低速，再逐步提速；每次只改一个参数。
